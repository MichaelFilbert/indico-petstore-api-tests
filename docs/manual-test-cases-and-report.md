# Task 1: Manual API test cases and execution report

**API:** Swagger Petstore v2, https://petstore.swagger.io/v2 (spec: https://petstore.swagger.io/v2/swagger.json)
**Tools:** Postman (collection in `postman/petstore.postman_collection.json`, run with Newman, output in `docs/postman-run.txt`) and curl (commands at the bottom of this page)
**Executed:** 22 October 2026, by Michael Filbert
**Expected results come from the Swagger spec:** `name` and `photoUrls` are required, `status` is one of `available | pending | sold`, POST invalid input = 405, findByStatus invalid status = 400, DELETE invalid id = 400, not found = 404.

## POST /pet: Add a new pet

| ID | Scenario | Steps / request | Expected | Actual | Result |
|---|---|---|---|---|---|
| TC-POST-01 | Create pet with all fields | POST `/pet` with id, category, name, photoUrls, tags, status=available | 200, body echoes the request | 200, body identical to the request | Pass |
| TC-POST-02 | Created pet is stored | After TC-POST-01, GET `/pet/{id}` | 200, same name and status | 200, same name and status | Pass |
| TC-POST-03 | Only required fields | POST `{"name":"minimal-pet","photoUrls":[]}` | 200, id generated by server | 200, numeric id generated | Pass |
| TC-POST-04 | Malformed JSON | POST body `{not valid json` | 4xx client error (spec: 405) | 400 `bad input` | Pass (status code differs from spec, noted) |
| TC-POST-05 | Missing required fields | POST `{"status":"available"}` (no name, no photoUrls) | 405 Invalid input | 200, pet created without name | **Fail, BUG-01** |
| TC-POST-06 | Status not in enum | POST with `"status":"flying"` | 405 Invalid input | 200, pet saved with status "flying" | **Fail, BUG-02** |
| TC-POST-07 | Wrong type for id | POST `{"id":"abc","name":"x","photoUrls":[]}` | 405 Invalid input | 500 `something bad happened` | **Fail, BUG-03** |

## GET /pet/findByStatus: Find pets by status

| ID | Scenario | Request | Expected | Actual | Result |
|---|---|---|---|---|---|
| TC-GET-01a | Status available | `?status=available` | 200, every item has status available | 200, 41 pets, all available | Pass |
| TC-GET-01b | Status pending | `?status=pending` | 200, every item has status pending | 200, 6 pets, all pending | Pass |
| TC-GET-01c | Status sold | `?status=sold` | 200, every item has status sold | 200, 34 pets, all sold | Pass |
| TC-GET-02 | New pet appears in results | Create pet with status sold, then `?status=sold` | Our pet is in the list | Our pet is in the list | Pass |
| TC-GET-03 | Response follows Pet schema | `?status=pending` | Each item has numeric id and photoUrls array | As expected | Pass |
| TC-GET-04 | Invalid status | `?status=invalidstatus` | 400 Invalid status value | 200 `[]` | **Fail, BUG-04** |
| TC-GET-05 | Missing required param | no `status` parameter | 400 | 200 `[]` | **Fail, BUG-05** |
| TC-GET-06 | Multiple statuses (spec: collectionFormat multi) | `?status=sold&status=pending` | Pets with sold or pending | Only sold pets (34) | **Fail, BUG-06** |

Note: the counts (41 / 6 / 34) change all the time because the Petstore is a shared public server.

## Commands used

```bash
B=https://petstore.swagger.io/v2
# TC-POST-01
curl -X POST $B/pet -H 'Content-Type: application/json' \
  -d '{"id":9223372000123,"category":{"id":1,"name":"Dogs"},"name":"MF-Doggie","photoUrls":["https://example.com/a.jpg"],"tags":[{"id":1,"name":"qa"}],"status":"available"}'
# TC-POST-05 / 06 / 07
curl -X POST $B/pet -H 'Content-Type: application/json' -d '{"status":"available"}'
curl -X POST $B/pet -H 'Content-Type: application/json' -d '{"name":"x","photoUrls":[],"status":"flying"}'
curl -X POST $B/pet -H 'Content-Type: application/json' -d '{"id":"abc","name":"x","photoUrls":[]}'
# TC-GET-01 / 04 / 05 / 06
curl "$B/pet/findByStatus?status=available"
curl "$B/pet/findByStatus?status=invalidstatus"
curl "$B/pet/findByStatus"
curl "$B/pet/findByStatus?status=sold&status=pending"
# TC-DEL-01 / 02 / 05
curl -X DELETE $B/pet/9223372000123
curl -X DELETE $B/pet/9223372000123
curl -X DELETE $B/pet/abc
```
